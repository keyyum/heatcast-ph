# HeatCast NCR dataset (real build)

Built on **2026-10-07 (UTC)** in Google Colab with `build_ph_heat_index_dataset.py`, from the Open-Meteo Historical Weather API
(`https://archive-api.open-meteo.com/v1/archive`, `models=era5`, timezone `Asia/Manila`, 2015-01-01 to 2025-12-29).
Scope: the 16 NCR cities of the PSA PSGC list. **These are gridded ERA5 reanalysis estimates for representative city
coordinates, not station observations and not 16 independent weather stations.**

| Folder / file | What it is |
|---|---|
| `output/ph_heat_index_next_day.csv` | the dataset: 64,240 rows × 26 columns (16 cities × 4,015 days, sorted by City, Date), 10.9 MB |
| `output/ph_heat_index_data_dictionary.csv` | column dictionary |
| `output/ph_heat_index_city_list.csv` | the 16 cities: coordinates, API elevation, ERA5 grid cell, provenance |
| `output/dataset_documentation.md` | source, method, formula, categories, limitations, validation (generated by the run) |
| `output/ncr_dataset_analysis.md` | pre-modelling analysis (generated by the run; the authoritative source for the numbers below) |
| `cache/raw/` | the 176 raw hourly API responses (gzip JSON), exactly what Open-Meteo returned |
| `cache/chunks/` | the 176 per-city-year daily aggregates built from them |
| `cache/city_list_base.csv`, `cache/run_log.txt` | the PSGC city list used; the run log (includes the self-imposed API pause) |

The generated files in `output/` are untouched artifacts of the run (for example, `dataset_documentation.md` records the API
budget caps that were in force then). SHA-256 of the CSV:
`b954754a5d5fecb5e8665d8efdfaeae6ba60376bfe3ce9c986ce5f9516332ed3`.

## Verify and reproduce (no API needed)

```bash
# 1. validate the committed dataset (read-only)
python build_ph_heat_index_dataset.py --validate-only data/ncr/output/ph_heat_index_next_day.csv

# 2. rebuild it offline from the committed cache and compare. Copy the cache first: a run appends to run_log.txt.
cp -r data/ncr/cache /tmp/ncr_cache
python build_ph_heat_index_dataset.py --work-dir /tmp/ncr_cache --out-dir /tmp/ncr_rebuild
cmp /tmp/ncr_rebuild/ph_heat_index_next_day.csv data/ncr/output/ph_heat_index_next_day.csv && echo identical
```

Both the aggregated chunks and, with `cache/chunks` deleted, the raw responses alone rebuild the CSV byte-for-byte (checked, and
guarded by `tests/test_committed_data.py`). If the aggregation logic ever changes, bump `AGG_VERSION`: the dataset is then
re-aggregated from `cache/raw` without calling the API.

## What the real data show (see `output/ncr_dataset_analysis.md` for everything)

* **Class counts, `HeatLevelTomorrow`:** Not Hazardous 158 (0.25 %), Caution 8,733 (13.59 %), Extreme Caution 50,018 (77.86 %),
  Danger 5,331 (8.30 %), **Extreme Danger 0**. The highest hourly-derived heat index in the whole dataset is **48.16 °C**
  (hottest hourly temperature 36.9 °C), so the 52 °C threshold is never reached in this ERA5 data.
* **Rare classes (flags only, nothing merged or dropped):** Not Hazardous is on only 16 distinct days / 13 episodes in 11 years
  (2 days in the proposed 2023-2025 test period); Extreme Danger is absent. Danger has 723 distinct days / 238 episodes.
* **Shared grid series:** the 16 cities resolve to **2 ERA5 grid cells** (10 + 6 cities) whose deseasonalised heat-index series
  correlate at ≥ 0.95; the effective number of independent series is **≈ 1.05**. Pressure, cloud, wind, rain and solar are identical
  for all cities in a cell.
* **Elevation adjustment:** Open-Meteo applies a standard lapse rate to temperature and dew point (≈ −0.64 °C per 100 m) and
  leaves relative humidity essentially unchanged. API elevations span only 2-51 m, giving a mean |ΔHI| of 0.21 °C between cities of
  one cell, which still moves 2.3 % of same-cell city-days across a class boundary.
* **Reference baselines on the proposed 2023-2025 test period (macro F1 over classes that occur):** persistence 0.532 (accuracy
  0.829), monthly climatology 0.330 (0.786), majority class 0.218 (0.773).
